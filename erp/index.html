The Legacy Problem

Fragmented Data & Slow Velocity

Why This Project Exists

Modern enterprises suffer from "Application Sprawl." Accounting uses one tool, HR uses another, and Inventory is managed on spreadsheets. This disconnect leads to:

  • Data Redundancy: Entering the same customer info 3 times.
  • Latency: Executives wait days for reports that should be instant.
  • Human Error: Manual syncing leads to financial discrepancies.

Nexus ERP solves this by centralizing the database and creating a unified service layer.

SYSTEM ARCHITECTURE v1.0
Waiting for user interaction...

01. Request Initiation

The workflow begins at the Presentation Layer. Users interact with the Thymeleaf/React frontend interfaces. Whether it's a purchase order or an employee leave request, the data is validated client-side and packaged into a secure JSON payload.

02. Business Logic Processing

The payload hits the Spring Boot Controller. Here, the Service Layer takes over. It checks permissions (Spring Security), executes complex business rules (e.g., "Is budget available?"), and prepares the transaction.

03. Persistence & Transaction

Data is committed to the Relational Database (MySQL/PostgreSQL) using Hibernate/JPA. The system ensures ACID compliance, meaning the inventory isn't deducted unless the invoice is successfully generated.

Core Modules & Functionality

Inventory Management

Tracks stock levels across multiple warehouses. Features include:

The backbone of the ERP. It handles:
